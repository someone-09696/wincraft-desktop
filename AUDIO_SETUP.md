# Virtual-cable 3D audio (Windows runtime testing still needed)

**What the code does:** Open the B launcher, select a placed panel, then choose **3D Audio...**. Select the virtual cable's *recording/input* side. WinCraft captures that cable at 48 kHz, downmixes stereo to mono, and plays it as a positional OpenAL source located at the panel. The listener follows the player's camera. Each active panel needs its own cable; stopping or detaching a panel closes its capture. OpenAL uses a thread-local context so the capture worker does not replace Minecraft's audio context. This builds against the Minecraft/LWJGL runtime but still needs testing with your Windows audio driver and shader/mod setup.

**Setup:**

1. Install a reputable Windows virtual audio cable driver. One example is [VB-Audio's official VB-CABLE page](https://vb-audio.com/Cable/). Follow that vendor's installation instructions, which may require a reboot. Do **not** install drivers from third-party mirror sites.
2. Keep your **real headphones/speakers** as Windows' default output and your **real microphone** as the microphone device for Discord/browser calls. Do **not** enable Windows' *Listen to this device* option on the cable. Changing global defaults can reroute Minecraft into the cable, which is not wanted.
3. In Windows **Settings → System → Sound → Volume mixer** (location may vary by Windows version), choose *CABLE Input* (the **playback** side) as the **output device** for **only the app you want spatialized**. Restart its playback if the output does not move. For a browser, routing affects its Windows process rather than just one tab.
4. In Minecraft 26.2 Fabric (OpenGL), press **B**, attach the app, then open B again and click **3D Audio...**. Choose *CABLE Output* (the **recording** side). This input must support 48 kHz stereo 16-bit PCM in Java Sound. If no virtual cable appears, check its installation/format in Windows sound settings. The app's existing microphone configuration remains unchanged.
5. Route only the intended app to that cable. Apps sent to the **same** cable are mixed and will appear at the panel assigned to it. Use a separate virtual cable for each app/panel pair if you want them to have separate positions.
6. **Stop audio** in the launcher before switching cables/panels or changing Windows devices. Restore the app's Windows output to your normal speakers when done.

**Limits and safety:** The audio path requires Java Sound, a virtual cable that exposes a 48 kHz stereo capture line, and an OpenAL device supporting `ALC_EXT_thread_local_context`. If that OpenAL extension is unavailable, WinCraft reports an error rather than switching Minecraft's audio context. Windows drivers, Minecraft's OpenAL output and other mods may still interact; verify on your PC. Some apps use unsupported, exclusive or protected audio, and low latency or zero glitches cannot be guaranteed. Stereo is downmixed to mono for OpenAL positioning. WinCraft does **not** access the microphone; voice chat can use the app's microphone if that app itself supports background capture and has Windows permission. Minecraft window focus can still affect push-to-talk and other app input.
